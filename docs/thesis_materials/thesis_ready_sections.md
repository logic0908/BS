# 论文可直接引用段落（谨慎版）

> 说明：以下文本为“可直接放入论文的中文草稿段落”。使用前可按学校模板调整语气与编号。

## 1. 项目材料说明

本系统的论文支撑材料主要来源于项目仓库中的真实代码、运行文档与实验产物。后端实现位于 `backend/`，前端实现位于 `frontend/`，实验文档位于 `docs/`，自动化脚本位于 `scripts/`。与评估相关的结构化产物主要位于 `runtime/eval_reports/` 与 `runtime/figures/`。本文所有工程结论均基于可追溯文件路径，不采用虚构接口、虚构实验或虚构截图。

## 2. 已有技术基础

当前系统采用 React + Vite + TypeScript 构建前端工作台，后端使用 FastAPI 提供接口服务，并通过 Celery + Redis 支持异步任务执行。歌声转换主链路采用 So-VITS-SVC，文本条件控制采用 TextStyleAdapter 与 internal_film 相关机制。系统默认模型预设为 `final_primary`，默认 speaker 为 `lain`，并在任务 metadata 中记录模型、参数与执行状态信息，便于答辩阶段进行过程解释。

写作时需单独说明：自然语言提示词中的「男声」等标签主要参与风格语义与适配器参数侧的控制，**不会**仅凭提示词文本就自动切换 So-VITS-SVC 的目标 `speaker`。默认输出音色仍由 **`final_primary` / `lain`** 决定；若需稳定男声听感，应依赖已配置的男声模型预设（如工程内已单独验证的 preset）或多 speaker 模型，并在文中与「提示词语义」区分表述，避免读者误读为自动变声部。

## 3. 实际完成功能

从接口与任务链路看，系统已实现上传、任务创建、任务状态查询、结果下载以及风格证据分析等核心能力。后端已注册 `POST /api/v1/upload`、`POST /api/v1/convert`、`GET /api/v1/tasks/{task_id}`、`GET /api/v1/tasks/{task_id}/result`、`POST /api/v1/style-analysis/compare` 等接口。系统同时保留了 StyleSinger 相关高级实验入口，但默认演示链路仍以 So-VITS-SVC 为主。

## 4. 尚未完成或效果不理想部分

主观听评为需补充材料，未补齐前不得用于效果优劣结论。`subjective_eval` 相关文件当前主要用于记录模板与流程。因此，本文不能将客观指标变化直接表述为“主观听感显著提升”。此外，虽然代码中存在 Demucs 调用路径，但默认配置包含 mock/fallback 策略，若要形成“真实分离已验证”结论，仍需补充严格配置下的实跑证据。

## 5. 系统测试材料说明

根据 `docs/thesis_materials/codex_audit_report.md` 文首所载审计日期与命令记录，在**该次**材料整理所对应的环境中曾执行后端与前端关键测试命令：后端 `pytest` 在该次运行中通过，前端单元测试在该次运行中通过，前端构建在该次运行中成功。上述内容仅可表述为「材料包所附审计记录下的可复现性旁证」，**不能**外推为任意时刻、任意机器上的永久保证；论文定稿前建议在本地重跑同一命令并更新数字与日期后引用。

## 6. 实验结果边界说明

客观指标文件（如 `objective_metrics_1000`）可用于展示 baseline 与 internal_film 条件下的量化差异趋势，但现有样本规模与主观评价材料尚不足以支持“显著主观优势”结论。更稳妥的写法应强调：系统已具备可复现实验框架和可追溯评估产物，后续需要通过更大样本与人工听评进一步验证风格控制效果。

## 7. 风险口径提示（写作时避免）

1. 避免写“后端 waveform 接口已实现”，因为当前仓库未确认存在 `GET /api/waveform` 或 `GET /api/v1/waveform`。
2. 避免写“主观评价已证明系统效果较好”，因为当前主观评分仍待补充。
3. 避免将 StyleSinger 描述为默认稳定主链路。
4. 避免将客观指标趋势直接等同于主观听感结论。
5. 避免写「提示词中出现男声等字样即自动切换为目标男声 speaker」；默认音色以 `final_primary`/`lain` 为准，男声听感依赖对应 preset 或模型配置（见第 2 节说明）。
